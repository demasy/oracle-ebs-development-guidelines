# Oracle EBS Developer Technology Landscape

**Baseline: Oracle E-Business Suite R12.2 · Reviewed: 27 October 2026**

This reference separates EBS technologies and components from the tools used to build, test, migrate, and diagnose them. It covers the common developer foundation (Core), the specialist tracks (Specialist), the knowledge of other subject areas such as functional, DBA and infrastructure (Awareness), and the platforms that depend on the project (Optional). The tables below give the level of each row.

| Level | Meaning | Example |
| :--- | :--- | :--- |
| **Core** | Working knowledge of the EBS developer foundation, including build, test and release. | Call a public API with the right application context and handle its message stack. Write a PL/SQL package that sets the WHO columns and handles its exceptions. |
| **Specialist** | Implementation expertise in a track (UI, Reporting, Workflow, Integration, Data or Product). The track is part of EBS itself. | Build an OAF page, a Publisher template or a workflow process. |
| **Awareness** | Some knowledge of another subject area, such as functional, DBA or infrastructure: its tools, techniques and terms. For example, Self-Service is a web page where an employee or a manager does their own task. The work itself belongs to that team. | Functional: read an HCM Self-Service page, such as Employee Self-Service, and explain which setup controls what the user sees. DBA: read an `adop` log and name the phase that failed. Infrastructure: read a certificate error and name the host. |
| **Optional** | An additional platform or tool that the team selects. EBS works without it. | Run a SonarQube scan if the team uses it. |

Optional applies only where the project uses the area.

The Specialist tracks:

| Track | Technologies | Tools |
| :--- | :--- | :--- |
| **UI** | OA Framework | OAF Development |
| **Reporting** | Reporting & Document Generation, Discovery & Embedded Analytics | Reporting Development |
| **Workflow** | Workflow, Approvals & Business Events | Workflow Development |
| **Integration** | Integration & Services, Desktop Integration, Alerts & Event Automation | Integration Testing |
| **Data** | Data Loading & Migration | Configuration & Artifact Migration |
| **Product** | Product & Mobile Specializations | — |

In the tables, tool alternatives are separated by `/`, and a level applies to the area, not to every named product. The Standards column links each row to the standards of this repository that contain its rules.

## Applicability notes

- **Data models and context:** Use [WHO-column conventions](https://docs.oracle.com/cd/E26401_01/doc.122/e22961/T302934T303920.htm), the [TCA model](https://docs.oracle.com/cd/E26401_01/doc.122/e48950/T172155T172158.htm), and the appropriate application and organization context for the business operation. Module-specific API contracts remain authoritative.
- **Version compatibility:** Match JDeveloper/OA Extension, Forms/Reports Builder, Java and desktop tools to the installed EBS stack and applicable Oracle certification and patch guidance. Database 19c references here explain utility/package behavior; use the equivalent documentation for the installed database release. See the [EBS Technology documentation library](https://docs.oracle.com/cd/E26401_01/nav/technology.htm) for the OA Framework Developer's Guide; My Oracle Support note 1315485.1 is cited as its companion reference.
- **Embedded Publisher documentation:** Oracle's [R12.2 Setup Guide](https://docs.oracle.com/cd/E26401_01/doc.122/e22953/T174296T206856.htm) directs readers to EBS online help and My Oracle Support note 1640073.1 for the XML Publisher Administration and Developer's Guide and Report Designer's Guide. Use those release-specific instructions for embedded Publisher.
- **Business data loading:** Use documented public APIs, open interfaces and import programs for EBS business transactions. [Data Pump](https://docs.oracle.com/en/database/oracle/oracle-database/19/sutil/oracle-data-pump.html) supports database data/metadata movement; it does not replace EBS business validation. Use it for appropriate custom/staging data with the applicable product contracts.
- **Artifact migration:** Select the loader for the artifact: FNDLOAD for supported AOL definitions, WFLOAD for Workflow definitions, XDOLoader for Publisher files, JPXImporter for BC4J substitutions, and XMLImporter/XMLExporter for OAF XML/MDS documents. Confirm the applicable procedures in the component guides linked above.
- **Tool editions and licensing:** [SonarQube PL/SQL analysis](https://www.sonarsource.com/products/sonarqube/downloads/) depends on the selected edition. SQL Monitor is a Tuning Pack feature and requires the applicable entitlement. An example tool in this document is not a requirement to purchase or install it.
- **Release responsibilities:** Developers need R12.2 online-patching compatibility knowledge; Apps DBAs normally execute and administer the patching cycle. Follow the [EBS Maintenance Guide](https://docs.oracle.com/cd/E26401_01/doc.122/e22954/toc.htm) for operations. Platform administration and hosting are separate responsibilities; additional product frameworks belong in the landscape when the project uses them.
